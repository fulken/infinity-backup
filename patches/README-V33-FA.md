# INFINITY — کیت تست v33 / F4 (نسل نهم)

## این پکیج چیست؟

**درایور v25 + اسکریپت v33** — مرحله‌ی **F4: صفحه‌جدول‌ها (PTE)**.
رانگ قبل (v32) F3 رو **در عمل اثبات کرد**: walk از EPROCESS واقعی،
داده‌ی پروسه بیرون از ایمیج، اسم‌های زنده از +0x5A8، صفر کرش.
تنها خطا (W2) هم ریشه‌یابی شد: تحمل شمارش اسکریپت، کورکاپانه بود —
نه باگ درایور. این نسخه اون رو هم درست می‌کنه و لایه‌ی بعدی رو اضافه می‌کنه.

## چرا F4 مهم است؟

تا حالا هر خواندن، به «این صفحه الان حاضره» تکیه می‌کرد (residency
assumption). F4 این فرض رو **حذف** می‌کنه: قبل از هر خواندن، خودِ
صفحه‌جدول‌ها رو می‌خونیم و Present بودن صفحه رو **اثبات‌شده** می‌بینیم.

## درایور v25 — op 12 (TranslateVa)

مسیر جدید، **بدون تعویض CR3** (درس v17/v19: اون کار VM رو می‌کشت)،
**بدون خواندن فیزیکی، بدون هیچ کال کرنل** — فقط از self-map ویندوز:

```
PTE_BASE کشف — دو زنجیره‌ی مستقل که باید توافق کنن:
  A: nt!MmPteBase از .data (دو RVA کاندید از ۱۹ PDB واقعی 19045)
     + چک ساختاری ۵۱۲-مقداری (چرت که قبول نشه)
  B: MmPfnDatabase → CR3 سیستم (EPROCESS+0x28) → _MMPFN.PteAddress
     → اتحاد s (پایه از خودِ صفحه‌جدول‌ها مشتق می‌شه)
پس از توافق A==B:
  اثبات دوجهته: PML4E[s] باید به فریم CR3 اشاره کنه —
  صفحه‌جدول‌ها EPROCESS رو ولوید می‌کنن، EPROCESS صفحه‌جدول‌ها رو.
سپس walk چهارسطحی با فرزند-تحت-والدِ حاضر (ذاتیِ بی‌خطا):
  PML4E → PDPTE → PDE → PTE + صفحات بزرگ 2MB/1GB.
```

**نکته‌ی ایمنی (مهم):** زنجیره‌ی A اول اجرا می‌شه و تا وقتی پاس نشه
هیچ خواندن خارج-ایمیجی انجام نمی‌شه — یعنی اگه بیلد ویندوزت با
هر دو RVA کاندید فرق داشته باشه، درایور **تمیز رد می‌کنه** و VM
زنده می‌مونه (هیچ ریسکی نیست؛ فقط گزارشش رو می‌فرست).

## اسکریپت v33 — تغییرات

1. **فیک W2 (کپ-آگاه):** مقایسه با `min(live, 64)` — دیگه دنیای
   «۱۰۲ پروسه» خطا نمی‌ده (رانگ v32: walked=64 live=102)
2. **نردبان P جدید:**
   - **P1**: op-12 روی pe_base — چهار سطح + کشف PTE_BASE + اثبات دوجهته
   - **P2**: op-12 روی EPROCESS سیستم — «لنگر F3… حالا PTE-ولیدیتد»
   - **P3**: op-12 روی پنجره‌ی KUSD — پایه‌ی J-ladder
   - **P4**: op-12 روی IDT
   - **P5/P6**: منفی‌ها (غیر-کانونیکال + محدوده‌ی user → ErrInvalid)
   - **P7**: cross-check: dtb از payload ی op-11 (فیلد جدید @1056)
     باید == cr3 از op-12 باشه — **دو مسیر مستقلِ درایور به هم می‌رسن**
3. رگرسیون کامل K/L/M/J/W مثل همیشه

## نصب (تعویض کامل — این بار هم درایور عوض می‌شه!)

این **FULL swap** هست، نه فقط-اسکریپت:
1. `usb-d\memory.efi` رو با `memory.efi` این پکیج عوض کن (v25-RT = **141154** بایت)
2. `usb-d\trigger-test-v33.ps1` رو کپی کن (v32 رو پاک کن)
3. `phase-d.bat` رو عوض کن
4. مثل همیشه بوت کن و phase-d رو اجرا کن

`phase-d.bat` قبل از هر کاری سایز + هش SHA-256 رو چک می‌کنه و
اگه درایور قدیمی باشه دقیق می‌گه کدوم نسخه‌ست و چرا رد شده.

## انتظار رانگ v33

- رگرسیون K/L/M/J/M **سبز** (هفتمین بار)
- **W1 همه PASS + W2 این‌بار هم PASS** (کپ-آگاه) → خط `>>> F3 PROVEN <<<` کامل سبز می‌شه
- **P1..P7 سبز** → `>>> F4 PROVEN: PAGE-TABLE TRANSLATION + RESIDENCY VALIDATION <<<`
- INFCNT = فرمول دقیق (G+8+13+4+4+6 = **37** با wSent=4 و pSent=6)
- اگر P1 با rc=2 رد شد: بیلد ویندوزت با RVA های ما فرق داره —
  **خیلی هم عالی**: درایور fail-closed کار کرد، VM زنده‌ست، فقط
  گزارش رو بفرست تا ثابت درست رو از PDB بیلد خودت دربیارم

ترنسپورت اثبات‌شده. 🚀
