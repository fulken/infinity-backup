# پکیج v30 — درایور v22 + اسکریپت v30 (F3: پیاده‌روی EPROCESS)

## خبر فیلد v29: سبز کامل — F2 در هر دو سطح بسته شد ✅

اجرای v29 (۲۰۲۶-۰۹-۲۷ ساعت ۰۵:۳۶) **۵۳ ثانیه، صفر کرش، VM زنده تا آخر**:
**M2r با مقدار کانونیک پاس شد** (`raw=0xF0004A65`، کلمه‌ی پایین = 19045 =
ground truth خودِ KUSD — تشخیص «باگ انتظار اسکریپت» درست بود) +
**INFCNT = 27 با نام‌گذاری هر ترم** (`G+8+13+4 = 27`) + هر سه حکم:
`PHASE E COMPLETE` + `F1 PROVEN` + `F2 PROVEN`. درایور v21 از ابتدا بی‌نقص
بود؛ v29 فقط انتظار اسکریپت را درست کرد. **حالا F3 نوبت خواندنِ بیرون از
image است.**

## درایور v22 چيست؟ سه لایه روی هم

1. **کل قرارداد v21 بازتولید شد (kx::)** — پچ سورس v21 در رول‌بک گم شده بود؛
   از باینری اثبات‌شده‌ی فیلد (`90bc3bdf...`) دستور‌به‌دستگاه مهندسی معکوس
   شد: `kx::Rd32` (دروازه‌ی RVA + خطای چسبنده + بودجه‌ی ۱,۰۰۰,۰۰۰ بایت) +
   کل walk اکسپورت با چیدمان واقعی فیلدها (`nFuncs@+0x14`, `nNames@+0x18`,
   `addrFuncs@+0x1C`, `addrNames@+0x20`, `addrOrds@+0x24`) + تشخیص forwarder و
   ردِ تمیز آن. **قرارداد سیم (payload ۶۴ بایتی، status codeها، ردیف‌های
   سریال [XS]/[KPCR]) دقیقاً همان چیزی است که v28/v29 با آن اثبات شد** —
   اسکریپت v30 با M همان قدیمی رگرسیون می‌گیرد.
2. **F3: پیاده‌روی EPROCESS (pw:: + op 11)** — از `PsInitialSystemProcess`
   که M1 حل می‌کند (گیتِ in-image — بدون ریشه‌ی اعتماد جدید)، لیست
   `ActiveProcessLinks` طی می‌شود با: **سازگاری دولینکِ LIST_ENTRY**
   (`Blink(cur)==قبلی` و `Blink(next)==cur` قبل از هر پیشروی)، **گیتِ VA
   کانونیک + عدم‌سرریز**، **پنجره‌ی خوشه‌ی pool با ±۴GB**، **سقف ۶۴ ورودی
   و ۲۵۶ صفحه‌ی خوانده‌شده**، و **کشف زنده‌ی جای‌نام** (۱۶ نامزد ۰x560..
   0x5D8 با کاوش `"System\0"` + رتبه‌بندی چاپ‌پذیری). کلاس مرگ v19
   (شکار نامِ hardcode شده) اینجا **از اساس ناممکن** است. هر امتناع = یک
   status تمیز؛ VM زنده می‌ماند.
3. **بافت v22** + گیت شش‌تاییِ بات (120678 / 121253 / 125450 / 128010 /
   131709 / 134330) — با v21 همه‌ی K/L/M/J سبز می‌ماند و فقط W با
   `ErrUnsupported` تمیز رد می‌شود (هرگز کرش).

## اسکریپت v30: نردبان W (جديد) + رگرسیون کامل

- **W1** — خودِ پیاده‌روی (op 11، outN=32): انتظار `status=1` + `payload.status=0`
  + **`sys == مقدار M1`** (تقاطع F2↔F3!) + `entries[0]` = System (pid 4) +
  نام‌ها با flags بیت ۰ و `"System\0"`
- **W2** — تقاطع زنده: pidهای پیاده‌روی‌شده باید در `Get-Process` باشند +
شمارش در تلورانس ≤۳
- **W3** — خودِ PowerShell (`$PID`) در لیست (اگر آن‌تر از پنجره‌ی ۳۲تایی
  ذخیره بود: NOTE صادقانه، نه FAIL)
- **W4** — منفی‌ها: `outN=0` و `outN=33` هر دو → `ErrInvalid(5)`، بدون کرش
- **W5** — بی‌ربطی pid: op 11 با pid واقعی هم Success (داده‌ی لیستِ کرنل
  گیت pid ندارد — در تقابل با J7)
- **INFCNT**: فرمول v29 + `$wSent` (هر op-11 یک +۱؛ op-11 هیچ InfinityData
  می‌نویسد — outN در هدر درخواست سفر می‌کند)
- **حکم F3**: `>>> F3 PROVEN: THE EPROCESS WALK - PROCESS DATA OUTSIDE THE IMAGE <<<`
