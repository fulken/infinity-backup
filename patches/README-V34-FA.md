# INFINITY — کیت تست v34 / F4 دومین تلاش (نسل دهم)

## این پکیج چیست؟

**درایور v26 + اسکریپت v34** — **F4: صفحه‌جدول‌ها، تلاش دوم.**
رانگ v33 اولین کرش تاریخ پروژه رو داشت (BSOD 0x50 داخل PowerShell)
و ما ریشه‌ش رو کامل پیدا کردیم: **باگ فرمول خودِ درایور v25** — نه
تنظیمات میدانی، نه بدشانسی. این نسخه همون باگ رو جراحی می‌کنه.

## صادقانه: در v33 چه اتفاقی افتاد؟

رگرسیون F1/F2/F3 **سبز ماند** (هفتمین بار)، فیکس W2 هم اثبات شد،
فیلد dtb هم درست اومد (0x1AD000). اما اولین op-12 (P1) با
**PAGE_FAULT_IN_NONPAGED_AREA (0x50)** VM رو کشت.

**ریشه (در سطح walk اثبات شده):** v25 آدرس‌های سطح‌های بالای
صفحه‌جدول رو با `PTE_BASE + shifted-vpn*8` حساب می‌کرد — این‌ها
اسلات‌های PTE **نیمه‌ی پایینِ user** هستن، نه اسلات‌های PML4E/PDPTE/PDE!
اولین خواندن PTE-space (self-ref در `PTE_BASE + s*8`) از PML4E[0]
**پروسه‌ی فراخوان** عبور می‌کنه — و در کانتکست اسکریپت PowerShell اون
درختون غایبه → فالت → کرش. دقیقاً همون چیزی که لاگ سریال و صفحه‌ی
آبی گفتن: موتور داخل pt::Translate مرد و هیچ‌وقت برنگشت ([PT]=0).

## فیکس v26 — فرمول‌های واقعی self-map

```
PDE_BASE = PTE_BASE + (s<<30)
PPE_BASE = PDE_BASE + (s<<21)
PXE_BASE = PPE_BASE + (s<<12)     ← PML4E[s] اینجاست: PXE_BASE + s*8
PML4E(V) @ PXE_BASE + ((V>>39)&0x1FF)*8
PDPTE(V) @ PPE_BASE + ((V>>30)&0x3FFFF)*8
PDE(V)   @ PDE_BASE + ((V>>21)&0x7FFFFFF)*8
PTE(V)   @ PTE_BASE + vpn*8       (این یکی از اول درست بود)
```

**زمینه‌ی حقیقت (ground truth):** این فرمول‌ها چهار ثابت کلاسیکِ
منتشرشده‌ی pre-1607 (با s=0x1ED) رو **دقیق** بازتولید می‌کنن:
`0xFFFFF6FB40000000` و `0xFFFFF6FB7DA00000` و `0xFFFFF6FB7DBED000`.
ضمناً هر اسلات اصلاح‌شده فقط از زنجیره‌ی self-ref خودِ s و والدهای
حاضر عبور می‌کنه — یعنی خاصیت «بی‌خطا ذاتاً» حفظ شده.

## چرا 89/89 تستِ v25 پاس شد ولی VM مرد؟ (درز شماره‌ی ۵)

چون **world مصنوعیِ تست host با همان فرمول غلط ساخته شده بود** —
موتور و world یک تصور مشترک اشتباه داشتن و همه‌چیز با هم موافق بود!
فیکس v26 **ساختاریه**: world حالا یک سلسله‌مراتب چهارسطحیِ **واقعی**
در حافظه‌ی فیزیکی شبیه‌سازی‌شده‌ست و PT_R8 با یک **walk مستقل
سخت‌افزاری** سرو می‌شه (فقط دنبال‌کردنِ entry های حاضر — هیچ اطلاعی
از فرمول‌های موتور نداره). PTE-space دیگه دستی مپ نمی‌شه؛ از خودِ
entry خودارج تمام‌عیار بیرون میاد — دقیقاً مثل سخت‌افزار واقعی.

## سه تغییر دیگر در v26

1. **اتحاد زنجیره‌ی B درست شد:** `PteAddress == PXE_BASE + s*8`
   (اسلات PTE خودِ صفحه‌ی PML4 — v25 با `PTE_BASE + s*8` مقایسه می‌کرد،
   پس B هیچ‌وقت توافق نمی‌کرد)
2. **selfOk بیت‌مبنایی شد:** بیت ۰ = «فضای PTE زنده‌ست» (اسلات
   self-ref حاضر + فریم سالم) — **این چیزیه که انتظارش رو دارید**.
   بیت ۱ = فریم self == CR3 سیستم — در کانتکست اسکریپتِ تریگر
   **صفر بودنش طبیعیه**: PML4 زنده، صفحه‌ی MALLِ خودِ همین پروسه‌ی
   PowerShell است نه صفحه‌ی سیستم (ادعای قدیمی v25 برای این کانتکست
   غلط بود و حتی بدون کرش هم خطای verdict می‌داد)
3. **گیت محدوده‌ی PtRd64 سرریز-امن شد** (برای s=0x1FF جمع سرریز
   می‌شد — تست T41 همینو گرفت!)

## انتظار رانگ v34

- رگرسیون K/L/M/J/W **سبز** (هشتمین بار) + خط `>>> F3 PROVEN <<<` تمیز
- **P1..P7 سبز** → `>>> F4 PROVEN: PAGE-TABLE TRANSLATION + RESIDENCY VALIDATION <<<`
  - P1: pteBase ساختاری + فریم سالم + **selfOk بیت۰=۱** (بیت۱ رو فقط
    اطلاع‌رسانی می‌کنه — صفر بودنش درستِ همینه)
  - P7: dtb از op-11 == cr3 از op-12 (دو مسیر مستقل درایور)
- INFCNT مثل v33: **37** (فرمول: G+8+13+4+4+6)

## مسیرهای رد-تمیز (بحران‌ناپذیر)

- **rc=2 (NoBase):** بیلد ویندوزت MmPteBase رو در هیچ‌کدوم از دو RVA
  کاندید نداره → درایور **قبل از هر خواندن خارج-ایمیجی** تمیز رد می‌کنه،
  VM زنده. فقط گزارش رو بفرست تا v27 ثابتِ بیلد خودت رو کد کنه
- **rc=4 (NotPresent):** صفحه‌ی هدف مپ نیست — جوابِ درست، نه خطا
- **selfOk=1 (فقط بیت۰):** طبیعی و سالم — یعنی فضای PTE زنده‌ست و
  کانتکست فراخوان یک پروسه‌ی user خودمونه

بعد از سبز شدن این رانگ: **Infinity.exe** (کلاینت userspace روی
ترنسپورت اثبات‌شده) — نردبان F1..F4 کامل می‌شه.
